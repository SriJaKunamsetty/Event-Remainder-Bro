# EventCraft

A planner for weddings, birthdays and community events (PromptWars Challenge 5: Celebration & Event Planner).
It turns a few facts about an event into a budget, a timeline and a vendor checklist that fit
the user's situation, and will add personalised ideas generated by Gemini.

> **Status: work in progress.** The planning engine (schemas, budget, timeline) is built and
> tested. The vendor checklist, feasibility check, AI ideas, UI and security headers are not
> built yet. This README describes what exists today and is updated as each part lands.

## Chosen vertical

**Celebration & Event Planner.** The persona is a first-time or occasional organiser, such as a
couple planning a wedding, a parent planning a birthday, or a volunteer running a community day.
They know roughly what they want but not what to do first, what it should cost, or what they
might be forgetting.

## Approach and logic

Budgets, dates and checklists are logic, so they are computed by deterministic, tested code in
`src/domain/`. The language model is reserved for what logic cannot do: personalised ideas and
turning plain English into the structured brief. This keeps numbers exact, makes the core
testable without any model, and means a model outage cannot break the plan.

| Context in the brief                      | What the engine does                                                      |
| ----------------------------------------- | ------------------------------------------------------------------------- |
| Event type (wedding, birthday, community) | Starts from a different budget split and a different task list            |
| Ranked priorities (up to 3)               | Weights those categories higher; rank 1 gets the largest boost            |
| Outdoor or hybrid venue                   | Adds logistics budget and a weather-backup task                           |
| Alcohol served                            | Adds permits budget and a licence task marked critical                    |
| Accessibility needs                       | Adds logistics budget (capped) and a venue access check                   |
| Dietary needs                             | Adds a menu or dietary confirmation task                                  |
| 100+ guests                               | Adds guest transport (weddings) or sponsor outreach (community)           |
| Event date close to today                 | Compresses all lead times by one ratio, keeps order, and reports the risk |

Every budget carries a plain-language rationale, so the user can see why the split looks the way
it does.

## How it works today

- `allocateBudget(brief)` reserves contingency first, then splits the rest by weight using the
  largest-remainder method, so the lines always add up to the total exactly.
- `buildTimeline(brief, today)` schedules each applicable task backwards from the event date.
  If less time remains than the longest lead needs, every lead is scaled by the same ratio and
  the schedule is marked `tight` or `critical`. The clock is passed in, never read.
- `EventBriefSchema` is the only definition of a valid request: unknown keys are rejected and
  every field has an upper bound.

## Assumptions

- Budget splits and lead times are common-sense starting points, not market data. They live in
  `src/domain/data/` so they can be tuned without touching logic.
- Money is an integer in the currency's minor unit; budgets are capped at 1e11 minor units so
  integer arithmetic stays exact.
- Dates are `YYYY-MM-DD` and handled as whole UTC days, so results do not depend on time zone.
- Nothing is stored on a server; a plan lives in the user's browser session.
- CI audits production dependencies only. At the time of writing, a high-severity advisory with
  no patched release affects dev-only lint tooling (`braces`, pulled in by `eslint-config-next`);
  it is excluded because it never ships to users. Revisit it before submission.

## Run it

```bash
npm install
npm run dev          # http://localhost:3000
npm run check        # typecheck, lint, formatting, tests with coverage thresholds
npm run build
```

Copy `.env.example` to `.env.local` and set `GEMINI_API_KEY` once the AI layer lands. The key is
read on the server only.
